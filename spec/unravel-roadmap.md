# Unravel Roadmap

Strategic backlog for the Causal Reconstruction Engine, captured after the trajectory review.
This is the "what we eventually build" document so deferred work is not lost. The flagship
build target in flight is Q3; Q1 and Q2 are queued behind it.

## Positioning (locked)

- **Track:** Security.
- **Front door:** incident-triggered pivot, not an ambient always-on console. The analyst is
  already in Splunk; a notable / host / time-window pivots them into Unravel for the causal story.
  Unravel complements the SIEM, it does not try to replace the alert queue.
- **Differentiator:** engine first, AI second. The agentic narrator is visibly doing real work
  (Q3), which separates us from "LLM wrapped around the alert queue" entries.
- **Generalization (vision only, not built):** the same provenance-graph + causal-chain engine
  maps to root-cause analysis in Observability. Mention as future surface; do not pivot tracks.

## Q1 - Incident-triggered pivot + `unravel` onboarding CLI

Kill the multi-flag incantation and the localhost-only friction.

- Interactive `unravel` command: prompt for Splunk URL/token, validate with a test search before
  committing, persist a named profile to `~/.unravel/` (not shell history / not the process list),
  then launch and open the browser. Subsequent runs reuse the saved profile.
- Entry scoped to a notable / host / time-window handed off from Splunk, rather than tailing the
  full firehose. The streaming engine stays; this is the analyst's front door onto it.
- **Doc-drift fix (do this with Q1):** `CLAUDE.md` documents `--earliest`, `--latest`,
  `--host-map`, `--incident-window`, `--incident-idle`, and `--retention`, but none exist in
  `engine/cmd/engine/main.go` on `main` (parseFlags stops at `--hec-sourcetype`). Either merge the
  branch that adds them or correct the docs before any judge runs the binary. A
  `./engine --incident-window=30m` today exits 2 with "flag provided but not defined."

## Q2 - One-click defensible incident report

The analyst's real job output is a writeup / ticket, not an on-screen dashboard. Today they
screenshot the graph and copy-paste prose by hand (no export anywhere in the UI).

- One button exports the active incident as a shareable report (Markdown and/or PDF): the causal
  chain, the backing evidence (raw events), the AI narrative + hypotheses, the recommended
  containment actions, and the threat-intel cross-references.
- Distinct from the existing HEC write-back, which sends structured JSON back to Splunk, not a
  human-readable artifact to the analyst.

## Deliberately NOT building (explicit non-goals)

These duplicate Splunk Enterprise Security / ticketing systems and re-fight the SIEM. Recording
them so they do not creep back in as "obvious" features:

- Triage queue / incident severity ranking / priority sort.
- Assignment and ownership ("assign to on-call").
- Incident state machine (investigating / escalated / closed), SLA, escalation timers.
- In-app collaboration (comments, @mentions). Real-time multi-analyst is out of scope.
